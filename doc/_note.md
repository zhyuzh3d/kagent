# 工作经验

## 模块开发重构原则

- 先吃透系统级前提，再拆模块。
- 用户明确的架构边界优先于我的推断。
- 先看认证和调用边界，再看单个服务内部实现。
- 不在术语未对齐时提前下结论。
- 对 Hub-Service 这种机制性设计，先按调用链和治理链判断。


## 模块清理

- 先判定当前 binary 的可达集，再决定删什么。
- 以入口和调用链为准，不以文件名、目录名、历史习惯为准。
- 先找整套未接入子系统，优先整套删，别零碎抠。
- 混合文件先保留活的 helper，再删死分支和旧协议。
- “未来可能会用”不算保留理由，当前可达、当前引用、当前生命周期依赖才算。
- 每轮删减后必须做构建/测试验证，再复查 diff 和状态。
- 清理目标不是整理目录，而是缩小当前真实可执行范围。
